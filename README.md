# PhishClass

> **Команда 14 (KIB-14)** · БПИ246 · НИУ ВШЭ Москва · 2026

Веб-приложение для экспресс-анализа подозрительных писем и URL. Определяет возможную технику фишинговой атаки, объясняет её риски и выдаёт пошаговый чеклист реагирования, специфичный для каждого класса угроз.

---

## Проблема

Фишинг стал многовекторным: ссылки составляют **60,1 %** всех атак, зафиксирован взрывной рост SVG-вложений (**в 50 раз**), обратных прокси AiTM (**+139,2 %**) и поддельных цепочек переписки через легитимные сервисы. ИТ-специалист МСП при получении жалобы тратит критическое время на ручной разбор типа угрозы и не всегда знает специфику реагирования (например, необходимость отзыва сессионных токенов при AiTM-атаке).

**Целевой пользователь:** системный администратор / ИТ-специалист МСП, получивший жалобу на подозрительное письмо.

**Гипотеза:** инструмент с автоматической классификацией по технике + готовым чеклистом сокращает время первичного реагирования по сравнению с ручным анализом по общим инструкциям.

## Поддерживаемые техники (таксономия)

| Ключ | Техника | Источник |
|------|---------|----------|
| `svg_attachment` | SVG-вложение | SRC-313 (Hoxhunt, 2024) |
| `qr_phishing` | Фишинг через QR-код | SRC-312 (KnowBe4, 2024) |
| `thread_hijacking` | Подмена переписки (Thread Hijacking) | SRC-313 |
| `reverse_proxy` | Перехват сессии через обратный прокси (AiTM) | SRC-312 |
| `credential_phishing` | Кража учётных данных | SRC-312 |
| `masked_url` | Маскировка адреса | SRC-312 |

## Аналоги и отличие

| Аналог | Что делает | Чего нет |
|--------|-----------|----------|
| PhishTool | Анализ заголовков письма | Нет чеклиста по конкретной технике |
| VirusTotal | Проверка URL / файлов | Нет классификации по технике атаки |
| Google Safe Browsing | Блокировка вредоносных URL | Нет реагирования и классификации SVG / AiTM |
| **KIB-14 PhishClass** | Классификация по технике + чеклист реагирования | — |

## Метрика успеха

На 10 синтетических письмах (по 1–2 на технику) приложение должно:
- Определить хотя бы одну технику корректно в **≥ 8 из 10** случаев
- Выдать ответ **за < 2 секунды** при локальном анализе

---

## Ключевые выводы исследования

1. **SVG и AiTM — новые приоритеты реагирования.** Традиционные антивирусы не блокируют SVG-вложения с JS; AiTM обходит SMS-MFA. Нужны специфические меры: FIDO2 против AiTM, блокировка SVG на почтовом шлюзе. *(SRC-312, SRC-313)*
2. **Единого индикатора фишинга нет.** Ни URL, ни вложение, ни отправитель по отдельности не дают уверенности — нужна комбинация сигналов. Комбинированный анализ текста + URL снижает долю пропусков.
3. **Время реагирования критично при AiTM.** Каждая минута с момента перехвата куки — потенциальный ущерб; готовый чеклист сокращает время первичного реагирования специалиста. *(SRC-314)*

## Запуск

Нужен Python 3.10 или новее.  
Для анализа через GPT перед запуском задайте `export OPENAI_API_KEY="ваш_ключ"`. Без ключа работает локальный анализ на правилах.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m streamlit run app.py
```

Откроется браузер по адресу **http://localhost:8501**

## Ограничения

- Анализирует текст письма и URL — не выполняет парсинг MIME-заголовков и бинарных вложений
- Работает на синтетических данных; не подключается к внешним базам репутации
- GPT-режим передаёт введённый текст в OpenAI API — не использовать с реальными конфиденциальными письмами
- Не заменяет профессиональный форензик-анализ; решение о реагировании принимает специалист
